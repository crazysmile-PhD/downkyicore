# v1.1.1 Dialog And Startup Hardening

## Goal

Fix Issue #123's shared custom-window regression, serialize startup-only modal flows, and make
legacy migration cancellation explicit without introducing a second dialog framework.

## Item A: Shared Custom Chrome

- `DialogWindow` uses `WindowDecorations="None"`, extended client decorations, no resize,
  minimize or maximize.
- The custom title region in `ViewAlertDialog`, `ViewAlreadyDownloadedDialog`,
  `ViewDownloadSetter`, `ViewParsingSelector`, `ViewUpgradingDialog` and
  `NewVersionAvailableDialog` has `WindowDecorationProperties.ElementRole="TitleBar"`.
- `ViewParsingSelector` and `ViewAlertDialog` use `ColumnDefinitions="*,50"`; close buttons are
  in column 1.
- Headless tests construct all six dialogs and prove borderless chrome, title-bar role and valid
  close-button layout bounds.

## Item B: Startup Modal Ordering

- One observed async startup flow awaits legacy-data migration before update checking.
- A deterministic test proves update UI cannot open while migration UI remains active.
- `AvaloniaDialogService` is not given a global semaphore; legitimate sequential dialogs elsewhere
  retain their current behavior.

## Migration Cancellation Contract

- User close and the visible cancel action open an explicit confirmation instead of immediately
  closing the dialog.
- Confirmed cancellation requests the migration token, awaits the migration task, observes late
  faults, and only then closes the modal.
- Continuing migration dismisses the confirmation without canceling the active operation.
- Host shutdown may bypass the user confirmation, but dialog teardown still cancels and awaits the
  owned migration before `ShowAsync` returns.
- The same idempotent async teardown owns `OnDialogClosedAsync` and `IAsyncDisposable`; no caller
  may dispose the token source while the migration still uses it.

## Verification And Rollback

Run strict Release build, Desktop headless/smoke tests, architecture tests and the full solution.
On Windows, visually confirm one title and one close action with draggable custom chrome. Roll back
the two items independently; neither changes user data or migration schema.
