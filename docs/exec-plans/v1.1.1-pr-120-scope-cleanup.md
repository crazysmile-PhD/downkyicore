## Root-Cause Review Investigation

### Protocol termination

Violated invariant: an API sequence may terminate only through its documented bound or terminal
signal. A valid empty payload is not a substitute for EOF.

Failure path:

```text
DmSegMobileReply.Elems is empty for a quiet six-minute bucket
-> GetAllDanmakuProtoAsync treats the bucket as EOF
-> later advertised buckets are never requested
-> the ASS artifact is silently incomplete
```

The earliest lost-semantic boundary is `GetAllDanmakuProtoAsync`: it discarded the separate
`DmWebViewReply.dm_sge.total` contract and compressed `empty bucket` and `end of sequence` into
one sentinel. The checked-in protobuf definition and current yutto/bilix implementations agree
that `/x/v2/dm/web/view` supplies the bound. The segment reply has no terminal marker.

Sibling search found one production segment enumerator. `DownloadArtifactWriter` already keeps
transport, protobuf parsing and cancellation distinct; those mappings remain unchanged. The
incorrect API-audit row, knowledge-graph contract and empty-segment regression are part of the
same failure family and must be replaced together.

| Metadata/segment outcome | Requests | Artifact outcome |
| --- | --- | --- |
| `total = 0` | metadata only | successful empty danmaku source |
| `total = N` with an empty interior bucket | exactly segments `1..N` | continue and retain later comments |
| missing `dm_sge` or invalid total | no guessed enumeration | protocol failure |
| malformed segment protobuf | stop at that segment | parse failure |
| transport/IO failure | no EOF inference | typed artifact failure |
| caller cancellation | stop immediately | cancellation propagates |

### Pipeline commit boundary

Violated invariant: downloaded source files, sidecars and persisted retry checkpoints remain
owned by the active task until all required validation succeeds and durable completion commits.

Failure path:

```text
mux succeeds
-> FfmpegProcessor/FfmpegConcatRuntime deletes source inputs
-> artifact, validation or durable completion fails
-> retry checkpoint still names files that no longer exist
-> retry downloads media again or cannot resume cleanly
```

The earliest destructive boundary is the FFmpeg owner, not the stage array. Reordering artifacts
ahead of mux reduces one trigger but still leaves validation and SQLite completion failures after
source deletion. The shared fix therefore covers DASH merge, single-segment DURL and multi-segment
DURL: mux publishes an output but preserves inputs; `FinalizeStage` performs exact-source cleanup
through the existing `DownloadTaskFileService` only after durable completion has committed.

| Failure/transition | Source and sidecars | Completed keys | Output | Durable state |
| --- | --- | --- | --- | --- |
| artifact failure | preserve | preserve | not required | failed, retryable by existing policy |
| mux failure | preserve | preserve | reject temporary output | failed |
| validation failure | preserve | preserve | preserve for diagnosis/retry | failed |
| completion persistence failure | preserve | preserve | preserve | not completed |
| cancellation before completion | preserve | preserve | preserve | existing cancellation transition |
| completion committed | post-commit cleanup | committed history owns result | preserve | completed |
| post-commit cleanup failure | preserve undeleted residue and log count | completed | preserve | remains completed |

Output-path reservation, overwrite policy and selective corrupt-input invalidation are different
invariants already owned by PR #125 and PR #127; this PR records but does not absorb them.

### Artifact file ownership

Violated invariant: every file created by an artifact operation is durably owned by the task,
directly or through an established sidecar base path, or does not exist when the operation exits.

Failure path:

```text
artifact writer chooses a path
-> physical write creates an invalid or partial file
-> validation fails before RecordTransferFileAsync
-> pipeline fails without a durable owner for the physical file
-> later task cleanup cannot discover the orphan
```

The earliest lost-ownership boundary is `DownloadArtifactWriter`, which previously persisted the
path only after validation. The fix claims the path through the existing task state writer before
the first filesystem write; it does not add a mutable path registry. Sibling-path search covered
main cover, page cover, subtitle tracks, default subtitle, danmaku and NFO. When a retry changes
an artifact path while reusing its logical key, the Application owner appends a deterministic
claim key instead of replacing the earlier durable path; no process-local path registry is added.

The permanent proof is a deterministic artifact state space spanning successful file producers
and cover failures before and after physical creation. The review invariant corpus separately
requires `deterministic-generative` and `adversarial-mutation` proof kinds. Its mutation profile
removes a durable owner and reruns the positive state-space proof; the Gate accepts the mutation
run only when TRX records real failed tests. A renamed or split test migrates its executable filter
without changing the required proof kinds, while an always-passing replacement fails the Gate.

## Exact-Head Review Follow-Up

- Danmaku metadata supplies the exact segment bound. Empty interior segments remain valid;
  transport, IO and protobuf failures are not end markers and still fail the requested artifact
  stage.
- The API audit records `/x/v2/dm/web/seg.so` as a production endpoint owned by the artifact flow.
- MySpace package selection uses the existing `DownKyiAsyncDelegateCommand` fault/cancellation
  observer rather than a second async-command policy.
- Main-window lifetime token is captured once before disposal; cancellation between legacy
  migration and update checking ends the startup flow without reading a disposed token source.
- The dialog adapter does not report a legacy migration modal closed until its owned migration
  task has terminated. Close cancellation, late task faults, and async disposal are observed by
  one lifecycle owner before startup can advance.
- Main cover keeps the compatible `cover` transfer key; page cover uses the distinct stable
  `page-cover` key so both paths survive persistence and cleanup.
- Every artifact output path is durably claimed before its first write. Subtitle siblings keep
  every prior durable path when language metadata changes across retries, and a deterministic
  state-space plus adversarial mutation proof guards the shared durable-owned-or-absent invariant.
- Danmaku metadata bounds that cannot be traversed by the inclusive `int` loop, including
  `int.MaxValue`, fail before any segment request; metadata, transport and EOF semantics remain
  distinct.
- Every custom-chrome caption button uses Avalonia's `User` decoration role rather than the
  draggable title-bar role. The migration dialog exposes the existing cancellation command and
  states that closing cancels migration.
- FFmpeg does not delete downloaded inputs. `FinalizeStage` cleans the exact committed task inputs
  and sidecars only after durable completion, while cleanup failure cannot roll completed history
  back to a failed state.
