# v1.1.1 Runtime Hardening

## Goal

Prevent corrupt, conflicting or unrecoverable download state from becoming a completed output.
Each numbered item is implemented in priority order on a dedicated branch after PR #120 scope
cleanup. Existing domain state, SQLite resume data and user settings remain compatible.

## P0: Data Ownership

1. Reserve normalized output paths atomically before task persistence. Compare active queued,
   downloading and paused tasks; use `OrdinalIgnoreCase` on Windows. FFmpeg finalization may not
   overwrite a destination owned by another task.
2. Distinguish invalid video/audio source from mux infrastructure failure. Invalid source revokes
   only its completed key, partial/sidecar and backend identity so retry downloads that source;
   missing FFmpeg or destination permission must preserve valid source files.

## P1: Retry And Validation Placement

3. A host/URL change may resume only with verified matching identity, range and total length;
   otherwise delete partial state and restart from byte zero.
4. Swallow cancellation only when the owning token is canceled. Unexpected task cancellation is
   a typed retryable failure and cannot leave a durable task in Downloading.
5. Transfer integrity belongs inside the coordinator retry loop. Invalid output can try a backup
   URL and one bounded playback-address refresh before final failure.
6. Duration tolerance uses a fixed upper bound and a small percentage, and expected-tail decode is
   independent of a shortened actual duration.
7. Validation accepts explicit required-stream flags; audio-required output must contain decodable
   audio through the tail with bounded audio/video duration drift.

## P2: Defensive Completeness

8. Reliable exact content length rejects both undersized and oversized files.
9. FFmpeg fail-on-error and deterministic multi-point/segment-boundary checks cover local damage.
10. DURL honors video-only/audio-only and transcoding choices.
11. No-resource outcomes for subtitles/covers are separate from API, conversion, write, permission
    and zero-byte failures. Required NFO output follows the same active-pipeline contract.
12. Reject duplicate, non-positive and malformed DURL order manifests before transfer.

## Verification

Every item requires a test that fails on the old behavior, strict Release build, all affected test
projects, architecture gates and `git diff --check`. Cross-platform or real-binary claims require
their existing runtime suites; no item may be marked complete from a mocked unit test alone when
the contract concerns Downloader, aria2 or FFmpeg behavior.

## Rollback

Revert one semantic item at a time. Never roll back by deleting user databases, completed history,
partial files or settings. A rollback must restore the previous code path and its corresponding tests.
