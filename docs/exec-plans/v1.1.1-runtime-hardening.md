# Runtime Hardening Quick Cards

用途：快速定位仍存在的 runtime 缺口。這不是 backlog；開始工作後，以對應的
GitHub Issue／PR 為狀態權威。

口訣：**找主、守界、取證、停手**。

## 起飛前

開始任何一張卡以前，必須同時具備：

- 可在最新 `main` 重現的症狀；
- 一句可驗證的不變式；
- 唯一 authoritative owner；
- 修改前會失敗的 regression；
- 明確 Stop：不順手修第二個問題。

缺一項，只診斷，不修改 production code。

## 快速索引

| 卡 | 症狀 | 先看 |

## H1 — Duration Authority

- 症狀：容許誤差為 `max(3s, expected * 5%)`；長影片的絕對誤差無上限。
- 守界：expected duration 決定容許範圍與 tail probe；actual duration 不得把
  自己的驗證點向前移。
- Owner：`FfmpegMediaValidator`。
- 取證：涵蓋長影片、截尾輸出，以及無法到達 expected tail 的 regression。
- Stop：不順手改 audio presence、transfer retry 或 DURL selection。

## H2 — Required Streams

- 症狀：輸出存在且影片可 decode，不代表要求的音訊也存在、可 decode、長度合理。
- 守界：`NeedsVideo` 必須證明 video；`NeedsAudio` 必須證明 audio；兩者都需要時，
  duration drift 必須有界。audio-only 不得因沒有 video 而失敗。
- Owner：尚未確認。先判定 media semantics 應由 `FfmpegMediaValidator` 還是 final
  `ValidateStage` 擁有；確認前只診斷。
- 取證：video-only、audio-only、audio+video、缺音訊與 tail decode regressions。
- Stop：不重新設計 DASH／DURL transport。

## H3 — Exact Length

- 症狀：已知長度時會拒絕 undersized output，但 oversized output 仍可能通過。
- 守界：只有 authoritative exact length 才能要求 `actualBytes == exactBytes`；
  estimate／advisory size 不得被升級成 exact contract。
- Owner：尚未確認。先證明哪個 size source 提供 exact contract；
  `DownloadFileIntegrity` 只負責執行已證明的 contract。
- 取證：exact undersized、exact oversized、unknown／estimated size regressions。
- Stop：在證明 size source 以前，不修改 equality 語義。

## H4 — DURL Requested Content

- 症狀：DURL 內部流程可能覆蓋使用者選擇的 video／audio 意圖。
- 守界：`RequestedContent` 決定輸出；transport format 只決定內部實作。
- Owner：`DownloadMediaStage` 的 DURL planning/finalization。
- 取證：video-only、audio-only、audio+video 與 configured audio transcode。
- Stop：不改 manifest `Order` 規則或建立第二套 DURL registry。

## 共用落地檢查

- 先保留修改前失敗證據。
- 只改同一 owner 的最小路徑。
- 跑 affected tests、strict Release build、architecture/review gates。
- `git diff --check`。
- 一張卡一個可獨立 revert 的 PR。

Rollback 不得刪除 database、history、partial files、settings、transfer identity 或
resume state。
