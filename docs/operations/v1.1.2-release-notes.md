# DownKyi v1.1.2

v1.1.2 修復影片詳情頁的手動操作按鈕狀態，並修正 macOS 最終 App
bundle 的簽章完整性發布邊界。

## 使用者可見修正

- 影片資訊載入或自動解析完成後，「解析影片」與「下載選中」會依目前
  狀態立即恢復可用，不再保留過期的 disabled Command 狀態。
- 非同步 Command 使用單一原子執行權，避免狀態通知與快速重複操作造成
  同一工作重入。
- macOS package 會先完成 App 內容複製與 aria2、FFmpeg 執行權限修改，
  再簽署內部 Mach-O 檔案與外層 App bundle。
- 最終 App 必須通過 `codesign --verify --deep --strict`，才可建立、雜湊與
  上傳 DMG；歷史 `code has no resources but signature indicates they must
  be present` 錯誤會直接使 release 失敗。

## macOS 發布信任邊界

Recovery workflow 只允許兩種明確模式：完整 Apple credentials 使用
Developer ID、notarization、stapling 與 Gatekeeper 驗證；完全沒有 credentials
則使用 ad-hoc identity `-`，但仍強制執行 strict codesign、DMG remount 與
實際啟動驗證。正式 Release notes 會附加本次實際採用的模式。

## 驗證範圍

本版本沒有修改 lifecycle、thread 或 process ownership。Recovery publish
必須引用同一 control-plane head 上成功的手動 Build run；該 run 仍執行正常
Assembly Lifecycle release gate。Recovery workflow 不重複該長測試，但會重新
執行三平台 package validation、macOS final-app strict codesign、SHA-256
sidecar、manifest 與 release asset gate。

## 相容性

- 保留既有 settings JSON、資料目錄及 portable mode。
- 保留 legacy SQLCipher SQLite、未完成任務、aria2 GID、partial file map、
  completed segment keys 與續傳狀態。
- 發布包不包含開發者 Cookie、帳號資料、Config、Logs、Cache、Storage
  或下載資料庫。
